# Ofrenda

**A memory altar that never leaves your device.**

Ofrenda turns a voice memo from someone you love into a printable remembrance
card. It runs Whisper and a 0.5B open-weight language model inside the browser
through WebAssembly — no backend, no account, no upload.

Built for **Hacktoberfest 2026 · DEV Challenge Week 4: Ghost in the Machine**.

**Live:** https://ofrenda-altar.app.workbuddy.host/?sharecode=KXM3HYYMEC

> Instant demo, no downloads: append `&demo=1` to that link.

---

## Why

Every "AI memory" product asks you to upload the most private thing you own —
a dead relative's voice — to a server you don't control, run by a company that
may not exist in five years. The recording is the last of that person that
still behaves like them. It should not depend on someone else's uptime.

Ofrenda inverts that. The audio is decoded by the Web Audio API, transcribed by
Whisper running on WebAssembly in the same tab, and turned into card copy by a
quantised open-weight model. Nothing is sent anywhere. The only bytes that
leave the page are model weights, pulled once from a CDN and then cached.

That is the point of the project, not a technical detail: **local inference is
what makes this idea ethically possible at all.**

## What it does

1. **Bring a memory** — record in the browser, drop an audio file, type it, or
   load the bundled sample.
2. **Read what was said** — Whisper transcribes on-device; the transcript is
   editable, because ASR is never perfect and the user is the authority.
3. **Who is on the altar** — name, relationship, one thing to keep, language,
   dates.
4. **The card** — a 1000 × 1400 SVG rendered in the page, exportable as a 2×
   PNG, printable, or shareable as a link that carries the whole card in the
   URL fragment.

## Architecture

| Stage | Technology | Where it runs |
|---|---|---|
| Audio ingest | Web Audio API (`OfflineAudioContext` at 16 kHz) | browser |
| Resampling to 16 kHz mono | hand-written channel mixer | browser |
| Speech to text | `onnx-community/whisper-tiny` (fallback `whisper-base`) via transformers.js | WASM, in-tab |
| Card copy | `onnx-community/Qwen2.5-0.5B-Instruct` q4, fallback `SmolLM2-360M-Instruct` | WASM, in-tab |
| Card render | inline SVG, generated by `src/card.js` | browser |
| PNG export | SVG → `Image` → `canvas.toBlob()` | browser |
| Hosting | any static server | none needed |

There is no server component. `grep -r "fetch(" src/` returns nothing.

### Deliberate design decisions

- **SVG, not canvas, for the card.** What you see in the page is byte-for-byte
  what gets exported. No `html2canvas`, no screenshot service, no font that has
  to be downloaded before the card looks right.
- **A text-first path.** ASR can fail: a bad microphone, an unusual accent, a
  network that blocks the model CDN. The app still works if you type the
  memory, and the writer model still does the writing. Degradation is a
  designed path, not an error screen.
- **A deterministic fallback writer.** If the 0.5B weights can't be fetched, a
  template composer builds the card from the transcript and the three fields.
  The status line always says which engine produced the words — the app never
  pretends a model ran when it didn't.
- **Three CDNs for transformers.js.** A single blocked CDN shouldn't decide
  whether a family's recording is readable. jsDelivr → unpkg → esm.sh.
- **The share link is a fragment.** `#<base64url>` carries the card. It is
  never sent to a server, because fragments aren't. Opening it renders the
  card and skips the workshop.

## Run it

Any static server works — there is no build step.

```bash
git clone <this repo>
cd ofrenda
python -m http.server 8087
# open http://127.0.0.1:8087
```

`file://` will not work: ES modules and WebAssembly need an HTTP origin.

### Model settings

Both models are selectable in the page:

- **Speech**: `whisper-tiny` (39 MB, fast) or `whisper-base` (145 MB, better
  with accents). Weights download once, then live in the browser cache.
- **Writer**: on by default. Turn it off for the instant demo path — the
  template composer needs no weights at all.

## Known limitations

- `whisper-tiny` is small. On long, quiet, or heavily accented recordings it
  will drop words. That is why the transcript is editable — the human is the
  correction layer.
- The 0.5B writer is a 0.5B writer. It writes competent, plain card copy. It
  will not write literature. The template fallback is, honestly, often better.
- First load downloads weights. On a slow connection that is a real wait, and
  the page says so instead of showing a spinner with no explanation.
- Safari's WebAssembly memory limits can make `whisper-base` fail; `tiny` is
  the safe default there.

## Privacy

No analytics, no cookies, no requests after the weights are cached. Recordings
live in a `Float32Array` in the tab and are gone when you close it. The share
link is generated only when you press the button, and it contains the card
text — not the audio.
